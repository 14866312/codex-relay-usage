# 关联用量：显式关系归属与运行时白名单读取边界

工具此前只统计当前线程，子代理与当前会话内的临时侧聊不进入任何数字。用户要求在主会话数值保持不变的前提下，看到同组的子代理与侧聊用量。本决策记录归属口径、每个成员的计量范围，以及为此扩大的只读边界。

## 决策

**归属只认显式关系。** 组根是当前识别或手动绑定的本地线程；成员来自会话元数据 `source.subagent.thread_spawn.parent_thread_id`（含多级子代理）与运行时的显式侧聊标记。相同标题、目录、时间、普通分叉、`agent_created_thread` 与 `root_turn_id != turn_id` 都不作为归属证据；父关系冲突或成环的线程列为“未确认”，既不猜归属也不计入合计。

**每个成员只贡献自身新增消耗。** 成员的 Token 以属于该线程的去重逐次调用为准；仅当报告的线程累计与调用合计一致时才视为完整。不一致时只计入自身调用并标注原因，因此分叉复制的父级历史不会被重复相加，也不会把不确定的累计数当成本成员用量。缺失不当零：只有累计数字、没有逐调用身份时展示该数字但排除在“已知合计”之外。

**侧聊用量只能来自运行时白名单投影。** 会话内侧聊是临时分叉，不写入本地 JSONL，也不进入 SQLite 线程表；扩大日志扫描无法覆盖。工具通过已确认主窗口进程的回环调试连接读取一份字段白名单：线程标识、侧聊标记、父导航路径与数字用量字段，在页面内直接构造结果，不先返回完整对象再过滤。这扩大了 [ADR-0007](0007-read-only-privacy-boundary.md) 中“只读路由元数据”的范围，但消息正文、请求体与凭据仍然不读、不传、不落盘。

**Token 覆盖与费用覆盖分开记录。** 侧聊只有运行时累计、没有逐调用身份，因此展示 Token、费用显示不可用，不生成虚构费用。关闭的侧聊在内存中保留最后一次观察值并标注“已不在观察中”；启动前已消失的侧聊与断线期间的缺口不做补回承诺。

**入口不可用时如实降级。** 运行时字段是版本相关的内部结构。本机 26.1007.2314.0 已验证可从主页面 React fiber 的 hook 值读取会话 store（`conversations` Map 的 `sideConversation`、`parentThreadId`、`sideConversationParentNavigationPath` 与 `latestTokenUsageInfo`）；未启用本地调试连接、字段缺失、结构变化或读取失败时，侧聊显示明确的数据不可用原因，不使用完整 IPC 会话状态或 SQLite 累计替代。子代理部分只依赖日志，不依赖该入口，Codex 更新后需用 `--runtime-usage-probe` 重新核实。

## 后果

- 子代理覆盖在只有日志的情况下即可工作；侧聊覆盖是“已观察且范围已确认”的下界，不是完整历史，也不能作为账单。
- 运行时适配器需要在 Codex 更新后重新核实；入口失效时功能降级为明确的不可用提示，而不是错误数字。
- 成员读取使用独立的分片读取与读取位置（最多 32 个成员，每成员每轮 1 MB），主会话发布不等待成员或运行时读取。
