# 与 Codex 的集成事实

本页记录工具依赖的 Codex 侧事实与边界：本地日志、页面路由、可访问性树、侧栏元数据与 IPC。实测覆盖 Codex 26.930.7945.0（路由结构）与 26.1007.2314.0（无障碍树就绪行为）；Codex 更新内部结构后这些事实可能失效，工具不承诺跨版本兼容。术语见 [CONTEXT.md](../CONTEXT.md)。

## 本地日志

- 默认目录为 `%USERPROFILE%\.codex\sessions` 及同级 `archived_sessions`；`CODEX_HOME` 环境变量或 `--sessions` 参数可覆盖。
- 会话文件为 JSONL；同一会话的活动与归档副本去重，只读其中一个文件。
- 读取是增量且只读的：文件追加通知直接触发读取，一秒扫描补偿；读到一半的内容（半行、未完成的 UTF-8 字节）等补齐再处理。
- 用量来源为逐次调用报告与 `thread_token_usage` 线程累计；两者是不同视图，绝不相加（见 [CONTEXT.md](../CONTEXT.md)“线程累计”）。
- 日志不包含逐个生成 token 的计数；单次调用在报告到达前没有准确用量，工具不猜测。
- 准确性边界：中转站可能漏报或改写 usage，Codex 也可能把缺失值归一化为零；日志不能还原上游真实值，统计不能直接作为账单。

## 模型目录（models_cache.json）

- 数据根（默认为 `%USERPROFILE%\.codex`，即 `sessions` 的父目录；`CODEX_HOME` 或 `--sessions` 覆盖时随之变化）存放 Codex 的模型目录 `models_cache.json`，条目字段含 `slug`、`context_window`、`max_context_window`、`effective_context_window_percent` 与 `auto_compact_token_limit`（实测 2026-10-12，约 691 KB）。
- 工具只按完整 slug 精确匹配，保留中转前缀、不做别名与模糊匹配；`context_window` 与 `max_context_window` 可以不同（本机 `codex-auto-review` 为 272,000／872,000），工具优先 `context_window`。`auto_compact_token_limit`（272,000×90% = 244,800）是自动压缩阈值，不是上下文窗口。
- 本机会话日志实测：目录 1M 的模型报告 `model_context_window` = 950,000（已含 95% 预留），272K 报 258,400，128K 报 121,600，另见 996,147（1,048,576×95%）。日志值已经是有效窗口，工具不会对它再乘一次 95%；`effective_context_window_percent` 只用于目录回退推导。
- 工具只读取该文件，从不写入；它变化时（即使日志没有追加）也会重新解析并发布，切换数据根会重建目录缓存。Codex 更新这些字段后需重新核实。

## 页面路由与本地调试连接

- Codex 以本地调试端口打开时，端口由系统分配；工具只发现“已确认主窗口进程拥有的 IPv4 回环监听”，只连接唯一的 app://-/index.html 主页面。
- 读取 MemoryRouter 的 pathname 与导航 key（每 100ms 有界读取）；不读取消息、请求体、凭据或对话正文，不注入持久监听器。
- 当前会话路由为 /local/<会话 ID>；首页与未知路由清空统计。连接超时（约 650ms）断开并清空，恢复后重读。
- 路由 ID、导航 key、窗口、进程生命周期与页面目标共同决定“代次”；切换时清空旧 Token 与费用并取消过时读取。
- 本地调试端口不对外网开放，但同机可访问该端口的程序具有浏览器调试能力——只使用可信的本机软件。
- 未启用调试连接时使用兼容识别（可访问性／标题／侧栏），不能保证同名唯一识别；调试连接曾建立后断开，不回退到标题猜测。

## 可访问性树与页面就绪

- 工具通过 Windows MSAA/IA2 读取应用主文档标题、侧栏行与项目标签；只读主文档与侧栏元数据。
- Chromium 的无障碍树按需构建：构建完成前页面只暴露尚未填充 URL 的文档节点（名称与子节点通常也为空，但工具的分类只看 URL：没有任何带可用 URL 的文档、且存在空 URL 文档即为待就绪）。此时状态是“当前页面尚未就绪”（等待），不是识别失败；就绪后自动恢复（见 [ADR-0002](adr/0002-identify-by-document-and-route.md)）。
- 等待文案按单调时钟分档，避免运行中一两秒的空窗闪烁：身份丢失时数字立即清空，不足 3 秒只显示“正在读取当前对话…”，达到 3 秒显示“当前页面尚未就绪”，达到 60 秒显示“等待较久，可尝试重启 Codex”（只出现在悬浮条内）。窗口生命周期（句柄、进程与进程启动时间）、日志目录或错误类型变化时重新计时；阻塞超时与调试连接断开保持即时提示。待就绪期间保留上一条侧栏绑定作为临时候选，页面恢复后重新核对文档、侧栏条目、标题与项目归属，全部一致才恢复绑定，超时（3 秒）或不一致即丢弃；空窗期间不发布数字。
- 实测（本机 Codex 26.1007.2314.0，2026-10-12 重启后）：主窗口出现后约 5–10 分钟内，窗口的无障碍树只有窗口装饰与一个未填充的文档节点，侧栏行同样读不到，因此这段时间没有任何可用的识别来源；08:38:48 启动 Codex，08:45:11 采样仍为待就绪，08:48:5x 文档才出现标题与 URL，08:49:19 生产路径完成侧栏识别。等待与窗口是否在前台无关（就绪瞬间窗口不在前台），同机 Edge 窗口与 Codex 自身的隐藏页面都能正常读出文档树，Codex 渲染进程也未带禁用无障碍的参数。
- 等待期间工具只做周期重读（150 ms；无窗口时 1 s）：不注入、不改写页面，也不因等待改变绑定状态；文档就绪后立即恢复识别与跟随。
- 待就绪时工具会主动请求一次有界的无障碍恢复走查：在独立 MTA 后台线程用原生 Windows UIA（CUIAutomation8；连接与调用超时各 250 ms）沿窗口原始视图读取节点类型，遇到 Document 边界即停止，由 Codex 自己完成页面树构建；只读节点类型，不读取名称、值、文本、输入框与正文，最多 128 个节点、深度 12、每父节点 64 个子项、总预算 1.5 秒。请求锚定首次等待：立即、2 秒、5 秒各一次，每个窗口生命周期（句柄／进程／进程启动时间）最多三次，成功后停止；窗口重建或退出使在途结果作废，底层卡住时不堆叠线程、监控线程不等待。走查不参与识别，页面身份仍由主文档读取重新确认（本机 2026-10-12 在运行中的 Codex 主窗口实测 31 ms 到达 document 边界）。
- 重启恢复样本（2026-10-12，同一登录会话内关闭并重启桌面端）：12:25:00 重启后 12:31:27 才恢复（约 6 分钟）；另一次受控重启窗口出现 4 秒后可见，t+6 s 采样仍是未填充文档节点（PENDING），t+8 s 即为就绪（约 2 秒），全程未做任何外部动作，工具轮询没有拖慢该过程。重启可尝试，恢复时间因环境而异；工具对两种情况都自动跟上。
- 侧栏行的节点身份是原生可访问性身份，不是 Codex 会话 ID；生命周期限于一个进程／文档，绝不写入设置。
- 可选的本机诊断“记录页面状态（本次运行）”只观察工具自身的读取与呈现结果（原始状态、呈现阶段、等待时长、窗口代次、悬浮条可见性与数字可用性），写入本机 `%LOCALAPPDATA%\CodexRelayUsage\diagnostics\`；不读取或记录标题、会话 ID、URL、用量数值与正文，也不改变 150 ms 周期重读与只读边界。

## 关联会话、子代理与侧聊

- 会话文件首行的 `session_meta` 携带显式关系：子代理写 `source.subagent.thread_spawn.parent_thread_id`（含 `depth`、`agent_path`、`agent_role`），并在顶层重复 `parent_thread_id`；分叉另有 `forked_from_id` 与 `subagent_history_start_ordinal`；`thread_source` 取 `user`／`subagent`／`agent_created_thread`。工具只读这一行的元数据，不解析无关会话历史。
- 子代理日志就是普通会话 JSONL，包含 `token_usage_record`（`thread_id`、`session_id`、`response_id`、`turn_id`、`usage`、`thread_token_usage`），因此可以按自身调用去重与计价。
- 实测（本机 26.1007.2314.0，2026-10-12，80 份子代理日志）：带 `forked_from_id` 的分叉子代理，其首条 `thread_token_usage` 等于自身首次调用（6 份样本：子 28,332–39,340 对父 8,471,997–22,722,545），即当前版本的子线程累计是自身范围，不含父线程累计。工具不依赖该结论：成员只在“线程累计与调用合计一致”时标记完整，否则只计入自身调用。
- 会话内侧聊（`ephemeral` + `sideConversation`）不写 JSONL：本机 313 份活动日志与 9 份归档中没有侧聊记录；`state_5.sqlite` 的 `threads` 表 295 行全部有 `rollout_path`，没有侧聊行；`thread_spawn_edges` 的 80 行与子代理日志一一对应。因此侧聊只能从运行时观察。
- 运行时用量入口已实测（本机 26.1007.2314.0，2026-10-12，Codex 以 `--remote-debugging-address=127.0.0.1 --remote-debugging-port=0` 启动）：会话状态位于主页面 React fiber 的 hook 值中，其 `conversations` Map 的每个值包含 `id`、`sideConversation`、`ephemeral`、`parentThreadId`、`forkedFromId`、`sideConversationParentNavigationPath` 与 `latestTokenUsageInfo`（`{total, last, modelContextWindow}`，数字字段为 camelCase，由 `thread/tokenUsage/updated` 更新）。白名单表达式在约 3,300 个 fiber 节点内命中，单次求值约 10 ms。
- 侧聊的 `parentThreadId` 为空，父关系由 `sideConversationParentNavigationPath`（`/local/<会话 ID>`）或 `forkedFromId` 解析；同页还存在不含用量的轻量元数据副本，表达式优先采用会话 store 的条目。字段缺失、结构变化或调试连接不可用时按不可用处理，不使用完整 IPC 状态或 SQLite 累计替代；Codex 更新内部结构后需用 `--runtime-usage-probe` 重新核实。
- 运行时投影保留固定预算（结果 64、会话 store 256、遍历 20 000 个 fiber 节点；本机实测约 3 300 个节点内命中），普通会话不占侧聊的结果名额。触发预算、字段缺失或读取失败时，读取结果给出原因与截断标记；工具保留上次观察值并把“已知合计”标为部分，只有成功完成的观察才能说明没有侧聊。

## IPC 订阅

Codex 的 IPC 连接会为同一客户端保留多个会话订阅，因此订阅不能作为“当前页面”信号；工具仅在诊断路径（--ipc-probe）使用它，生产识别以主文档与本地路由为准。

## 其他

- 同名对话、标题截断、侧栏隐藏：优先由路由 ID 唯一识别；无法唯一识别时提供“自动识别”（复制深链）与手动绑定。
- 深链复制依赖 Codex 的 Ctrl+Alt+L 快捷键；被改动或不支持时明确提示。
- 远程主机或云对话日志不在范围内；多个可见主窗口会停止自动识别。
