# 费用与速度口径

本页记录金额、速度与 Token 数字的计算口径。术语见 [CONTEXT.md](../CONTEXT.md)；日志侧事实见 [codex-integration.md](codex-integration.md)。

## 费用（估算）

- 金额为美元，单价为 USD / 1M tokens；使用 decimal 计算，统一三位小数（如 `$0.067`），小额正数显示 `<$0.001`，零显示 `$0.000`；收起槽与明细同一格式。
- 输入侧分三项：输入（含缓存读取与缓存写入）、缓存读取、缓存写入；输出单独一项。逐次按含缓存总输入选择档位。
- 两种计价模式：基础价乘倍率、直接折后价；可关闭的双档价格按阈值区分高低档；模型别名需精确完整匹配；支持分模型汇总。
- 账本按请求身份去重并与 turn_id 的模型匹配；历史缺口与异常记录会被标注。累计快照只用于 Token 展示与核对，不参与费用。
- 改价后在后台重算历史；费用发布前核对会话代次、账本身份与版本、价格版本，确保 Token 数据有效。
- 价格独立保存（`%LOCALAPPDATA%\CodexRelayUsage\prices.json`），原子保存；保存失败保留原文件并提示，界面不切换到未保存价格。
- 边界：这是按本地日志与个人配置的估算，不是中转站账单；中转站漏报／改写或 Codex 归一化零值都无法还原。

## 速度（输出速度）

- 主口径为“纯生成”：本轮累计输出 ÷ 生成类条目（Reasoning、AgentMessage）的累计时长；工具等待（命令、文件改动、MCP 调用）单列，不计入分母。
- 条目计时只在 turn_id 与 task_started 当前轮一致、时长大于 0 且不超过 1 小时时计入；新轮开始清零累计；turn_aborted 保留已累计的生成时长。
- 没有条目计时的轮次回退“本轮平均”（总耗时口径），展开行标签会标明当前口径。
- 速度按轮归属推进，在账本去重之前观测；≥100 tok/s 不丢弃小数位。
- 诊断：--speed-log-probe 按纯生成口径复算，输出生成秒数、工具秒数与生成占比，不含会话 ID、模型名与 Token 数量。

## 数字口径（Token）

- Token 用量优先使用逐次记录的 thread_token_usage 线程累计；较小快照不会降低该值；没有线程累计时使用去重调用合计；调用与累计快照绝不相加。
- 缓存读取已包含在输入中；未缓存输入 = 输入 − 缓存读取；缓存命中 = 缓存读取 ÷ 输入。
- 上下文占用 = 最近一次调用用量 ÷ 可用窗口（“最近调用估算”），不使用会话累计总量。
- 可用窗口：日志 `model_context_window` 有效时直接采用（它已含 Codex 的预留，不再乘第二遍比例）；日志缺失或为零时按完整模型 ID 精确匹配当前数据根（`sessions` 的父目录）的 `models_cache.json`：优先 `context_window`、缺失用 `max_context_window`，乘 `effective_context_window_percent`（缺失按 95%）向下取整；目录缺失时使用内置映射（核验日期 2026-10-12），都没有则显示“未知上限”，占比与剩余显示 `—`。
- 配置窗口为目录（或内置映射）给出的值；目录推导值与日志窗口不一致时标注“（目录参考）”，计算仍采用日志窗口。`auto_compact_token_limit` 是自动压缩阈值，不参与窗口计算。
- 模型切换（`turn_context` 换模型）清空旧模型的上下文读数与窗口；会话累计与账本不受影响。
- 轮次 = 按 turn_id 去重的 task_started 数量。
- 异常值（负数、缓存大于输入、推理大于输出、总量不一致等）显示异常提示，不用输入加输出伪装为正常值。
- 展开面板的上下文块显示完整模型 ID、配置窗口与剩余可用；会话 ID、更新时间与状态页脚仍不绘制，取数来源可通过本机诊断查看。

## 关联用量（子代理与侧聊）

- 分组只在费用明细的“关联用量”页出现：主会话、子代理、侧聊各一栏，另有“已知合计”。悬浮条的 Token、缓存、上下文与速度仍只反映主会话，不做跨线程求和。
- 归属只认显式关系（子代理的 `source.subagent.thread_spawn.parent_thread_id`、运行时侧聊标记）；冲突、缺失与成环列为“未确认”，不计入合计。普通分叉、`agent_created_thread` 与同名同目录都不并入。
- 每个成员只贡献自身新增消耗：以该线程去重的逐次调用为准；报告的线程累计与调用合计一致时标记“已确认”，不一致时只计入自身调用并标注原因（例如分叉继承基线），因此父 100 + 分叉新增 30 显示 130，而不是 230，且整体不标记为完整。
- 只有累计数字、没有逐调用身份时（旧格式日志、侧聊运行时累计），Token 照常展示但不进入“已知合计”，费用显示不可用；缺失不当零，也不生成虚构费用。
- 侧聊只有运行时累计，没有调用身份与档位信息，因此只报 Token；关闭的侧聊保留最后一次观察值并标注“已不在观察中”，启动前已消失的侧聊与断线期间的缺口不做补回承诺。
- 成员计价各自使用独立缓存，改价后与主会话一起按价格版本重算；分组发布前核对根会话、选择代次、关系版本与价格版本。
